# PomidorQA — автотесты на Playwright + TypeScript

Автотесты для [PomidorQA](https://aiqa.su/pomidorqa) — сервиса коротких встреч для
QA/IT-специалистов. Продукт доступен как живой сайт (`aiqa.su/pomidorqa`), здесь — только
автотесты и вспомогательный код для них.

Тесты построены по пирамиде: unit для чистых функций, API-тесты против локального мок-сервера
и e2e-сценарии в реальном Chromium на живом стенде.

## Установка

```bash
npm ci
npx playwright install chromium
```

Node.js 24+.

## Запуск тестов

```bash
npm run test:unit   # unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу
npm run test:e2e    # e2e — реальный браузер на живом aiqa.su/pomidorqa
npm test            # все три уровня сразу
npm run report      # открыть HTML-отчёт последнего прогона
npm run coverage    # полный прогон + метрики + генерация docs/coverage-matrix.md
```

Дополнительно:

```bash
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
```

По умолчанию e2e-тесты бьют в продакшен (`https://aiqa.su`). Чтобы направить на другой
стенд — переопределите `POMIDORQA_BASE_URL`:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## Покрытие требований

Покрытие считается не по числу файлов и не по строкам кода, а по функциональным требованиям
MVP из [`requirements.md`](requirements.md) — их в эталоне 50 (R3.1–R12.3). Каждый тест несёт
номера закрываемых требований в аннотациях Playwright:

```ts
test("время слота показывается в поясе владельца", {
  annotation: [{ type: "req", description: "R5.5" }],
}, async ({ page }) => { ... });
```

Аннотации попадают в JSON-отчёт прогона, а `scripts/test-metrics.mjs` сопоставляет их с
эталонным списком [`docs/requirements.json`](docs/requirements.json) и печатает сводку:
сколько требований покрыто, распределение по уровням пирамиды, что осталось без тестов и
что недостижимо в black-box. Актуальная матрица по всем 50 требованиям — в
[`docs/coverage-matrix.md`](docs/coverage-matrix.md); она генерируется из реального прогона
командой `npm run coverage` и руками не редактируется.

### Известный дефект

- **R8.3** — поиск в каталоге идёт по навыкам обоих типов, а не только «могу помочь»:
  участник находится и по навыку из «хочу разобрать». Тест написан по требованию и помечен
  `test.fail()` (`e2e/known-defects`): пока дефект жив, прогон зелёный; когда починят —
  Playwright сообщит «expected to fail, but passed», и пометка снимается.

## Структура

```
docs/              эталон требований (requirements.json) и генерируемая матрица покрытия
src/pyramid/       вспомогательный код: чистые функции (unit) и локальный мок-сервер (api)
tests/unit/        unit-тесты
tests/api/         API-тесты
tests/e2e/         e2e-сценарии по функциональным областям требований
tests/pages/       Page Object: локаторы и действия страниц
tests/helpers/     данные и вход: фабрика пользователей, регистрация через UI и API, слоты хоста
scripts/           подсчёт метрик и генерация матрицы покрытия
```

Сетап пользователей идёт через API — тесты проверяют бизнес-сценарий, а не форму регистрации.
Созданные аккаунты удаляются в `afterEach`, вместе с ними каскадом уходят навыки, слоты
и бронирования.

## CI

GitHub Actions (`.github/workflows/playwright.yml`) гоняет цепочку fail-fast на каждый
push в `main` и на каждый pull request: линт и типы → unit → API → e2e. HTML-отчёт
Playwright выкладывается артифактом после каждого e2e-прогона — включая упавший.

Финальная джоба `coverage` скачивает JSON-отчёты трёх уровней, считает метрики и покрытие
требований и пишет их в summary run — цифры видны прямо на странице прогонa, без скачивания
артефактов.
