# PomidorQA — автотесты на Playwright + TypeScript

Автотесты для [PomidorQA](https://aiqa.su/pomidorqa) — сервиса коротких встреч для
QA/IT-специалистов. Продукт доступен как живой сайт (`aiqa.su/pomidorqa`), здесь — только
автотесты и вспомогательный код для них.

Тесты построены по пирамиде: unit для чистых функций, API-тесты против локального мок-сервера
и e2e-сценарии в реальном Chromium на живом стенде.

## Установка

```bash
npm ci
npx playwright install chromium
```

Node.js 24+.

## Запуск тестов

```bash
npm run test:unit   # unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу
npm run test:e2e    # e2e — реальный браузер на живом aiqa.su/pomidorqa
npm test            # все три уровня сразу
npm run report      # открыть HTML-отчёт последнего прогона
```

Дополнительно:

```bash
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
```

По умолчанию e2e-тесты бьют в продакшен (`https://aiqa.su`). Чтобы направить на другой
стенд — переопределите `POMIDORQA_BASE_URL`:

```bash
POMIDORQA_BASE_URL=http://localhost:3000 npx playwright test --project=e2e
```

## Что покрыто

- **Unit** (`tests/unit/`) — пересечение слотов по времени, форматирование времени,
  валидация пароля: чистые функции из `src/pyramid/`.
- **API** (`tests/api/`) — регистрация, бронирование слота, гонка за один слот двух
  гостей — через HTTP к мок-серверу, поднятому прямо в тестовом процессе.
- **E2E** (`tests/e2e/`):
  - бронирование слота: хост публикует навык и слот, гость находит его в каталоге
    и бронирует встречу;
  - гонка за слот: двое гостей открывают один слот до подтверждения — бронирует первый,
    второй получает ошибку занятости, встреча видна обоим;
  - отмена бронирования хостом и гостем;
  - поиск в каталоге по навыку;
  - профиль: смена имени, добавление навыков;
  - негативный логин: неверный пароль → сообщение об ошибке.

Сетап пользователей идёт через API — тесты проверяют бизнес-сценарий, а не форму регистрации.
Созданные аккаунты удаляются в `afterEach`, вместе с ними каскадом уходят навыки, слоты
и бронирования.

## Структура

```
src/pyramid/       вспомогательный код: чистые функции (unit) и локальный мок-сервер (api)
tests/unit/        unit-тесты
tests/api/         API-тесты
tests/e2e/         e2e-сценарии
tests/pages/       Page Object: локаторы и действия страниц
tests/helpers/     данные и вход: фабрика пользователей, регистрация через API, слоты хоста
```

## CI

GitHub Actions (`.github/workflows/playwright.yml`) гоняет цепочку fail-fast на каждый
push в `main` и на каждый pull request: линт и типы → unit → API → e2e. HTML-отчёт
Playwright выкладывается артифактом после каждого e2e-прогона — включая упавший.
